# 宁波92号汽油调价提醒

云端数据检查 → 更新 `data/check.json` → GitHub Actions验证并发送邮件。
不需要电脑保持开机，不使用独立App或付费搜索API。

## 当前状态

代码已实现；是否已部署、数据检查任务ID和CI结果以本次交付说明为准。
配置邮件Secrets前，邮件链路不可用。SMTP接受邮件不等于QQ收件箱已送达。

## 开通邮件（仅两项Secrets）

在仓库 Settings → Secrets and variables → Actions 中配置：

- `SMTP_USER`：指定的接收QQ邮箱。服务从这个邮箱发送给它自身。
- `SMTP_PASSWORD`：该QQ邮箱开通SMTP后生成的授权码，不是QQ登录密码。

不要将授权码放入Issue、代码、聊天或普通Variables。
收件人仅从加密的SMTP_USER配置读取，不允许油价数据指定收件人，也不允许额外收件人、抄送或密送。
Secret值由用户在GitHub页面亲自填写；服务只读取运行时环境变量。

然后在 Actions → Fuel reminder → Run workflow 勾选 `test_email` 发送唯一一封测试邮件。
只有测试成功并确认收件箱收到，才能称为邮件端到端验收通过。
再次运行已成功发送的同一测试不会重复发送。

## 行为

- 数据检查任务的目标时间为北京时间每天09:00，云端调度可能延迟，非准点SLA。
- 核实本轮实际窗口日期；不把上一轮简单加14天。
- 以窗口标注日（例如X日24时）的前3个自然日发送首封；若当天运行失败，剩余窗口内可补发。
- 后续仅在加油建议类别改变时补发。金额变化但建议不变不发；官方确认但建议不变不发。
- 预测须有48小时以内的可信来源，明确对应本轮浙江/宁波92号元/升。
- 不将全国汽柴油混合幅度、元/吨或95号价格冒充当地92号幅度。
- 只有区间时不擅自取中值，当前实现记为幅度缺失。
- 价格使用已核实的浙江/宁波92号公开价格作为参考；省级最高零售价不代表每家加油站实际成交价。
- 价差为 `200 / 当前每升价格 * 每升涨跌`；默认明显门槛5元，见 `config.json`。
- 上涨达到门槛：近期需要加油且有余量时，生效前加200元。
- 小涨：正常按需加200元。
- 下降：油量够用则生效后加200元；不足先加50—100元，金额取决于近期用车需求。
- 日期已知但幅度/价格不足：说明数据不足，正常按需，不编造幅度或等待收益。
- 日期不能核实：不猜测日期、不发误导邮件；数据任务报告异常。

## 去重与重试

`.service/state.json` 是云端持久状态；工作流全局串行。发送前先通过GitHub CAS保存占位。
明确的临时SMTP拒绝或发信前网络故障最多3次尝试（首次+2次重试）。
在发送数据阶段发生连接中断，结果记为 `uncertain`，停止自动重发，避免重复。
`accepted` 只表示SMTP服务商接受，不表示进入收件箱。失败状态会让工作流显示失败。
遇到 `uncertain`，先检查收件箱/已发送，再人工修复状态，不能直接删除状态重跑。

## 修改、暂停、删除

- 修改门槛：编辑 `config.json` 的 `significant_difference_yuan`，提交后生效。
- 修改检查时间：修改ChatGPT中的“宁波92号油价数据检查”任务（北京时间）。
- 暂停：先暂停该ChatGPT任务，再到 Actions → Fuel reminder → Disable workflow。
- 恢复：恢复两者。
- 删除：删除ChatGPT任务，移除邮件Secrets，再删除仓库或工作流；删除仓库不可逆，应自行确认。
